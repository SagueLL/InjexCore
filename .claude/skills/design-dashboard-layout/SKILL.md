# PURPOSE

Design dashboard layouts that transform complex technical information into clear, usable, and scalable user interfaces.

The skill should help users understand operational state, priorities, risks, and trends without being overwhelmed by raw technical complexity.

---

# RESPONSIBILITIES

- Design dashboard page layouts
- Define information hierarchy
- Organize dashboard sections
- Define navigation structure
- Define overview pages
- Define detail pages
- Define card, chart, table, and timeline placement
- Support industrial dashboard clarity
- Support responsive layout planning
- Support future UI scalability

---

# NON-GOALS

- Do not define backend data contracts
- Do not modify data pipelines
- Do not invent unavailable metrics
- Do not prioritize aesthetics over clarity
- Do not create overly complex layouts for v0
- Do not make product strategy decisions autonomously

# INPUTS

---

# WORKFLOW

1. Identify dashboard objective
2. Identify target user and usage context
3. Identify available data contracts
4. Define primary information hierarchy
5. Group information into dashboard sections
6. Define page layout and navigation
7. Identify responsive considerations
8. Produce dashboard layout specification

# QUALITY BAR

- Prioritize clarity
- Prioritize operational usefulness
- Keep layouts simple for v0
- Preserve future scalability
- Avoid unnecessary visual complexity
- Ensure every section has a clear purpose
- Support fast user understanding

---

# FAILURE BEHAVIOR

If dashboard requirements are incomplete:

- explicitly state limitations
- propose a minimal layout
- identify missing requirements

If data contracts are unavailable:

- design only provisional structure
- avoid data-specific assumptions
- identify required contracts
